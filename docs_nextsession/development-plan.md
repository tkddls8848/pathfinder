# 개발 계획 — 음성 안내 개편 및 음악·라디오

작성 2026-08-05, 갱신 2026-08-08. 브랜치 `main`.

---

## 1. 배경

안내 음성이 기계음처럼 들린다는 지적에서 출발했다. 원인을 파 보니 두 층이었다.

| 층 | 원인 | 상태 |
|---|---|---|
| 음색 | 보이스를 고르지 않고 `setLanguage(KOREAN)` 만 호출 → 기기 기본(대개 최저품질 embedded) 보이스가 잡힘 | 수정 완료, 테스트 통과 |
| 문안 | 안내가 전부 명령형·`~습니다` 서술 | 개편 완료(3.4절), 테스트 통과 |

이후 **"무조건 사람 같은 음성이어야 한다"** 는 요구가 확정되면서 방향이 바뀌었다.
시스템 TTS는 기기마다 깔린 보이스가 달라 품질을 **보장할 수 없다**. 어르신 타깃일수록
저가·구형 단말 비중이 높아 최악의 경우를 밟을 확률이 오히려 크다.
설정에서 목소리를 고르게 하는 것도 답이 아니다 — 어르신이 조작해야 할 것이 늘고,
결국 보호자가 세팅해 줘야만 동작하는 기능이 하나 더 생긴다.

## 2. 확정된 방향: 음성을 미리 만들어 앱에 넣는다

이 앱은 자유 발화를 하지 않는다. 말하는 문장이 정해져 있다.

```
고정 문구      ~15개    "벨을 누르세요. 다음 정류장에서 내립니다."
숫자 슬롯     ~150개    숫자 0~9(버스번호) · 1~60분 · 1~30정거장 · 걸음 수
──────────────────────────────────────────────────────
              ~165개    opus 24kHz 모노 기준 1.5MB 이하 → 앱에 번들 가능
```

빌드 시점에 한 번 생성해 넣고 런타임에는 재생만 한다. 얻는 것:

- 기기와 무관하게 **항상 같은 사람 목소리**
- **완전 오프라인** — 버스 안에서 데이터가 끊겨도 하차 알림이 살아있다
- **설정 없음** — 어르신도 보호자도 건드릴 것이 없다

> 애초에 "음질이냐 오프라인이냐" 는 트레이드오프라고 판단했으나(로컬 보이스 우선 정책),
> 이 구조에서는 둘 다 성립한다. 그 트레이드오프 자체가 사라진다.

### 정류장·목적지 이름 — 유일한 예외

전국 정류장 이름을 미리 녹음할 수는 없다. 처리 방식:

1. 경로를 확정하는 시점(어르신이 집에서 "성모의원까지" 를 누를 때, 보통 와이파이)에
   그 여정에 필요한 이름 클립 2~6개만 받아 디스크에 캐시한다.
2. 버스 안에서는 캐시에서 오프라인 재생한다.
3. 못 받은 이름이 있으면 **그 문장 전체**를 시스템 TTS로 넘긴다.
   조각을 섞지 않는다 — 문장 중간에 목소리가 바뀌는 것이 가장 어색하다.

### 3.1 `VoiceGuide.kt` 보이스 선택 (커밋 전, 테스트 통과)

- 한국어 보이스를 전부 훑어 최적을 골라 `setVoice()`.
  규칙: 한국어 && 설치됨 → 로컬 우선(없으면 네트워크) → 품질↓ → 지연↑ → 이름순
- 이름순 정렬은 품질·지연 동률일 때 **실행할 때마다 목소리가 바뀌지 않게** 하기 위한 것.
- 엔진은 시스템 기본을 존중. 기본 엔진이 한국어를 아예 못 할 때만 대체 엔진 최대 2개 시도.
- 견고화: `onInit` 을 메인 루퍼로 미룸(일부 기기에서 생성자 안 동기 호출),
  `getVoices()` NPE 방어, `setLanguage` 반환값 확인, 초기화 콜백 정확히 1회 보장,
  실패 시 죽은 엔진 바인딩 정리.
- `activeVoice: VoiceCandidate?` 노출 (진단용).
- 테스트 `app/src/test/.../VoiceSelectionTest.kt` 9케이스.
  `android.speech.tts.Voice` 는 단위 테스트에서 못 쓰므로 선택 규칙을
  `VoiceCandidate` 값 객체 위의 순수 함수로 분리.

> **2절 방향이 확정되면 이 코드의 위치가 바뀐다.** 폐기가 아니라
> "클립이 없을 때의 폴백 경로" 로 남는다. 폴백도 최선의 보이스를 써야 한다.

### 3.4 문안 개편 (커밋 전, 테스트 통과)

원칙은 **상황별 이원화**다. 긴급 3종은 명령형 그대로 두고, 나머지를 해요체로 바꿨다.
긴급 안내는 몇 초 안에 몸을 움직여야 하는 것이라 부드럽게 돌려 말하면 판단이 늦어진다.

```
그대로 둔 것 (긴급 3종)
├ "벨을 누르세요. 다음 정류장에서 내립니다."
├ "곧 내립니다. 일어날 준비하세요."
└ "○○입니다. 내리세요."
   + "손을 드세요" — 3종에는 없지만 같은 성격이라 명령형을 남겼다.
     앞의 "곧 옵니다" 만 "곧 와요" 로 바꿨다.

바꾼 것
├ 약 150걸음 걸어서 성모의원으로 가세요  → 이제 성모의원 쪽으로, 백오십 걸음쯤 걸어가시면 돼요.
├ 3분 뒤에 옵니다                       → 삼 분 뒤에 와요. 조금만 기다리시면 돼요.
├ 계단 없는 저상버스입니다              → 계단 없는 버스라 타기 편하실 거예요.
├ 3정거장 남았습니다                    → 세 정거장 남았어요.
├ 정류장에 도착했습니다                 → 정류장에 다 왔어요.
└ 도착했습니다. 성모의원 앞입니다        → 다 왔어요. 성모의원 바로 앞이에요.
```

**수사 버그 수정.** `VoiceGuide.nativeCountToSpeech` 를 추가했다.
정거장·걸음은 순우리말 수관형사를 쓰는 단위라 `3정거장` 을 "삼 정거장" 으로 읽으면 틀린다.
백부터는 순우리말 수사가 현대어에서 쓰이지 않으므로("백쉰 걸음") 숫자를 그대로 넘긴다.
`분`·`번` 은 한자어 단위라 손대지 않았다.

**말하는 곳을 전부 훑었다.** `JourneyController` 뿐 아니라 톡백이 읽는
`contentDescription` 도 같은 버그를 갖고 있었다.

| 위치 | 고친 것 |
|---|---|
| `JourneyController` | 안내 문장 전체 |
| `GuidanceScreen` `spokenLabel` | 걸음·정거장 수사, 말투 |
| `Components.BusNumberTag` | 톡백이 "칠천십육번" 으로 읽던 것 → "칠 공 일 육 번" |
| `JourneyGuidanceService` 알림 | **손대지 않음.** 잠금화면에서 눈으로 읽는 글자라 숫자가 맞다 |

원칙: **눈으로 읽는 숫자와 귀로 듣는 수사를 분리한다.**

곁가지로 조사 버그 하나가 사라졌다. `"${destinationName}으로"` 는 받침에 따라
`으로`/`로` 가 갈려 "센터으로" 가 나올 수 있었다. `"~ 쪽으로"` 로 바꾸면서 없어졌다.

테스트 `app/src/test/.../SpeechTextTest.kt` 10케이스.

### 3.5 빌드가 처음 잡아낸 기존 컴파일 에러 (커밋 전, 테스트 통과)

이번 세션에서 쓴 코드가 아니라 **전부터 있던 것**이다. 컴파일을 한 번도 안 돌렸으니
드러날 수가 없었다. 이 다섯 개 때문에 `:app:compileDebugKotlin` 이 실패했다.

**1. `import androidx.compose.foundation.lazy.item` (4개 파일)**

`items` 는 최상위 확장 함수라 임포트되지만, `item` 은 `LazyListScope` 의 멤버다.
임포트할 대상이 아니다. `LazyColumn { }` 안에서는 수신 객체로 이미 보인다.
임포트 줄만 지웠다. `Home` · `Route` · `Search` · `SettingsScreen`.

**2. `HttpLoggingInterceptor.redactQueryParams` (`NetworkModule.kt`)**

이 API 는 OkHttp 5부터다. 이 프로젝트는 4.12.0 을 쓴다.
의존성을 올리는 대신 `Logger` 를 감싸 정규식으로 지우게 했다.

이건 단순한 컴파일 에러가 아니다. **없는 API 를 부르고 있었으니 마스킹은 처음부터
동작한 적이 없다.** 공공데이터포털은 인증키를 쿼리로 받고 `Level.BASIC` 도 요청 줄에
전체 URL 을 남기므로, 디버그 빌드 로그에 키가 통째로 찍히는 상태였다.

### 3.6 오디오 포커스 (커밋 전, 테스트 통과) — 4절 #6

**포커스 요청이 아예 없었다.** `AudioAttributes` 로 길안내 속성만 붙여 놓고
`requestAudioFocus` 는 한 번도 부르지 않았다. 속성은 "내 소리는 이런 성격이다" 라는
선언일 뿐이고, 다른 앱을 실제로 비키게 하는 것은 포커스 요청이다.
음악·라디오를 붙이기 전부터 이미 문제였다 — 어르신이 다른 앱으로 라디오를 듣고 있으면
하차 안내가 그 위에 그냥 겹쳐 나갔다.

**`urgent: Boolean` 을 `Priority` 3단계로 바꿨다.**

| | 앞 문장 자름 | 다른 앱 소리 | 쓰는 곳 |
|---|---|---|---|
| `NORMAL` | 아니오 | 덕킹 | 도보·대기·이동중 |
| `INTERRUPT` | 예 | 덕킹 | 상태 전환 안내, 다시 안내받기 |
| `CRITICAL` | 예 | **일시정지** | 벨·하차준비·하차·손을 드세요 |

불리언 하나로는 두 축을 못 담는다. "앞 문장을 자를지" 와 "음악을 멈출지" 는 대체로
같이 가지만 늘 같지는 않다 — 정류장 확인 직후 노선 안내는 지금 알려야 하지만
라디오를 멈출 일은 아니다. 등급을 셋으로 끊은 이유는 **`CRITICAL` 을 아껴 쓰기
위해서다.** 음악을 멈추는 것은 꽤 큰 개입이라 몇 초 안에 몸을 움직여야 하는 안내에만 쓴다.

구현에서 실제로 위험한 것은 **포커스를 놓지 못하는 경우**다. 음악이 영원히 멈춘 채로
남고, 어르신은 왜 라디오가 안 나오는지 알 방법이 없다. 세 군데를 막았다.

- `QUEUE_FLUSH` 로 앞 문장을 자르면 그 문장의 `onDone` 은 오지 않는다.
  자를 때 `pending` 을 같이 비운다.
- 엔진이 콜백을 끝내 안 주는 경우가 있다. 30초 워치독이 강제로 놓는다.
  가장 긴 안내가 12초 남짓이라 정상 동작을 자를 일은 없다.
- `stop()` · `shutdown()` 에서도 놓는다.

`speak()` 는 안내 루프(백그라운드 코루틴)에서 불리고 포커스 해제는 메인에서 돈다.
같은 필드를 만지므로 포커스 조작은 전부 메인 큐로 몰아 순서를 고정했다.

포커스를 **못 받아도 말은 한다.** 다른 앱이 배타 포커스를 쥐고 있다는 이유로
하차 안내가 통째로 사라지는 것이 훨씬 나쁘다.
반대로 통화 등으로 포커스를 잃으면 안내를 멈춘다 — 얹어 봐야 둘 다 안 들린다.

테스트 `app/src/test/.../VoicePriorityTest.kt` 7케이스.

### 3.7 에뮬레이터 실행에서 나온 것 (2026-08-08)

Pixel 6 · API 35 에뮬레이터에 설치해 눌러 봤다. 크래시 없이 돌고
홈·설정·검색 화면 전환, 입력 폼, 인증키 없음 안내가 모두 동작했다.

**글자가 단어 중간에서 잘린다.** 홈 화면 노란 카드가
"앱 설정이 끝나지 않았습니 / 다", "보여주세 / 요." 로 깨진다.
앞줄에 자리가 남았는데도 쪼갠다. Compose 기본 `LineBreak.Simple` 이 한국어를
CJK 로 보고 아무 음절에서나 끊기 때문이다. 이 앱은 본문 22sp·제목 34sp 라
한 줄에 들어가는 글자가 적어 일반 앱보다 훨씬 자주 걸린다. → 4절 #11

**에뮬레이터로는 음성 질문에 답할 수 없다.** 다만 이유가 처음 본 것과 다르다.

`tts_default_synth` 설정값이 `null` 이라 한국어 보이스가 아예 없는 줄 알았는데,
3.8절에서 설정 화면에 보이스를 띄워 보니 하나 잡혔다 — `ko-KR-language`, 품질 "좋음".
설정값이 비어 있어도 엔진은 기본값으로 동작한다. **설정 화면 하나가 추측을 뒤집었다.**

그래도 결론은 같다. 잡힌 것은 이름 있는 화자가 아니라 **언어 단위 대체 보이스 하나뿐**이다.
이 앱이 풀려는 문제는 "기기마다 다른 보이스 중 어느 것이 잡히는가" 인데,
후보가 하나뿐인 환경에서는 그 선택 규칙이 시험되지 않는다.
`google_apis` 이미지에는 Play 스토어가 없어 화자를 더 받을 수도 없다.

**`activeVoice` 를 볼 방법이 없다.** 진단용으로 만들어 놓고 UI 어디에도 안 나온다. → 4절 #12

### 3.8 화면 두 가지 (커밋 전, 테스트 통과) — 4절 #11·#12

**줄바꿈 (#11) — 완료. 다만 처음 시도한 방법은 틀렸다.**

먼저 `EodigaTypography` 에 `LineBreak(HighQuality, Normal, WordBreak.Phrase)` 를 넣었다.
**아무 효과가 없었다.** `WordBreak.Phrase` 는 일본어 문절 단위 끊기용이고 한글에는
적용되지 않는다. API 34 이상인 에뮬레이터에서 확인했으므로 버전 문제도 아니다.
CSS 의 `word-break: keep-all` 에 해당하는 것을 안드로이드는 노출하지 않는다.

한 화면에서 갈랐다. 같은 카드의 제목에만 워드 조이너(U+2060)를 넣고 본문은 그대로 뒀더니
제목은 "앱 설정이 끝나지 / 않았습니다" 로 어절에서 끊기고,
본문은 "보여주세 / 요." 로 여전히 잘렸다. 원인과 해법이 한 장에 같이 찍혔다.

그래서 `String.keepWordsWhole()` 로 갔다. 글자 사이에 폭 0인 워드 조이너를 끼워
그 자리의 줄바꿈을 금지한다. API 26 부터 전부 동작한다.

**호출부가 77곳이라 하나씩 고치면 반드시 빠뜨린다.** `ui/components` 에 머티리얼과
같은 이름의 `Text` 를 두고 화면들의 임포트만 바꿨다 — 파일당 한 줄, 전부 커버된다.

두 가지를 조심해야 했다.

- **이모지가 깨졌다.** 🔍 는 UTF-16 에서 두 칸(서로게이트 쌍)을 차지하는데
  그 사이에 조이너가 들어가 화면에 두부(◆?)가 떴다. 조이너를 넣는 조건을
  **양쪽이 글자·숫자일 때**로 좁혀 막았다. 이 조건이 공백·문장부호도 같이 걸러낸다.
- **낭독에는 원래 문자열을 준다.** 워드 조이너가 TTS 발음에 어떻게 작용하는지
  엔진마다 보장되지 않는데, 이 앱에서 음성은 곁다리가 아니라 주 출력이다.
  `contentDescription` 으로 깨끗한 문자열을 따로 준다.

테스트 `app/src/test/.../KoreanTextTest.kt` 10케이스. 이모지 회귀도 고정했다.

**안내 목소리 표시 (#12) — 완료.**
`activeVoice` 를 `StateFlow` 로 바꾸고 설정 화면에 카드로 냈다.
초기화가 비동기라 화면이 먼저 그려질 수 있어서 값이 아니라 흐름이어야 했다.

```
안내 목소리
ko-kr-x-ism-local
아주 좋음 · 기기에 저장됨
```

이 값이 필요한 이유는 하나다 — **기기마다 다른 목소리가 잡힌다.**
"소리가 이상하다" 는 문의가 왔을 때 어떤 보이스가 물렸는지 모르면 재현할 수 없다.
설정 화면은 보호자가 보는 곳이라 이 정도 기술적 표현이 허용된다.
`VoiceGuide.describeVoice()` 는 순수 함수라 테스트로 고정했다.

### 3.9 인증키를 넣고 처음 호출해 봤다 (2026-08-08)

**개발용 입력칸을 붙였다.** 에뮬레이터에는 마이크가 없어 음성 화면을 통과할 방법이
아예 없었다. `SearchScreen` 에 `BuildConfig.DEBUG` 로 감싼 입력칸과 표본 버튼을 뒀다.
`BuildConfig.DEBUG` 가 상수라 릴리스 빌드에서는 호출부째로 사라진다.

"넘기기" 버튼이 아니라 **입력칸**으로 만든 이유가 있다. 건너뛰면 정작 확인해야 할
공공데이터 조회가 확인되지 않는다. 이 칸은 음성 결과와 똑같이 `SearchViewModel.search()`
로 들어가므로 실제 경로를 그대로 탄다. 실제로 그 덕에 아래 버그가 드러났다.

표본 버튼을 같이 둔 것은 에뮬레이터 기본 IME 가 영문뿐이라 한글을 치려면
언어를 따로 추가해야 하기 때문이다.

**버그 — 병·의원 API 베이스 URL 에서 기관코드가 빠져 있었다.**

`HospitalApi` 의 KDoc 에는 `base url: https://apis.data.go.kr/B552657/` 라고
정확히 적혀 있는데, 정작 주입되는 Retrofit 은 `DATA_GO_KR_BASE = "https://apis.data.go.kr/"`
였다. 주석이 맞고 배선이 틀린 경우다.

공공데이터포털은 호스트가 같고 **기관코드로 서비스를 가른다.** 그래서 이 실수는
인증 오류가 아니라 `NO_OPENAPI_SERVICE_ERROR`("해당 오픈API 서비스가 없거나 폐기됨")
로 돌아온다. 키를 의심하게 만드는 오류라 원인을 찾기 어렵다.

고친 뒤 응답이 **400(서비스 없음) → 403(키 미등록)** 으로 바뀌었다. 경로는 해결됐다.
상수 이름도 `DATA_GO_KR_BASE` → `HOSPITAL_BASE`, 한정자도 `datagokr` → `hospital` 로
바꿨다. 뭉뚱그린 이름이 기관코드를 빠뜨린 원인으로 보인다.

**키는 유효하나 데이터셋 승인이 하나뿐이다.** curl 로 네 곳을 찔러 갈랐다.

| 데이터셋 | 결과 |
|---|---|
| 기상청 단기예보 (1360000) | **통과** — 파라미터 오류만 반환(키는 인정됨) |
| 버스정류소정보 (TAGO 1613000) | `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` |
| 버스도착정보 (TAGO 1613000) | `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` |
| 병·의원찾기 (B552657) | `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` |

이 두 오류를 구분하는 것이 핵심이다. `NO_OPENAPI_SERVICE_ERROR` 는 **경로**가 틀린 것이고
`SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 는 **경로는 맞는데 그 데이터셋에 신청이 안 된 것**이다.
후자가 돌아왔다는 것은 곧 **TAGO 세 경로가 전부 올바르다는 뜻**이기도 하다 —
아직 한 번도 성공 응답을 못 봤지만 주소는 맞다.

남은 것은 코드가 아니라 포털에서의 활용신청이다. → 4절 #13

**곁가지 — 3.5절의 로그 마스킹이 실제 로그에서 확인됐다.**
`serviceKey=***` 로 찍힌다. 5절에 "고쳤지만 실제 로그로 확인 못 함" 으로 적어 뒀던 항목이다.

### 3.12 음악 재생 (2026-08-09, 에뮬레이터 검증 완료) — 4절 #7

3.6절에서 비켜주는 자리를 먼저 만들어 뒀으므로, 여기서는 재생기만 붙이면 됐다.
`MusicLibrary`(MediaStore 조회) · `MusicPlayer`(재생·포커스) · `MusicScreen`(화면) 셋이다.

**포커스 규칙이 안내와 정반대인 자리가 하나 있다.** 안내는 포커스를 못 받아도 말한다 —
하차 안내가 통째로 사라지는 것이 더 나쁘기 때문이다(3.6절). **음악은 반대로,
포커스를 못 받으면 재생하지 않는다.** 통화나 다른 안내 위에 노래를 얹는 것이 언제나 더 나쁘다.
같은 앱 안에서 두 규칙이 반대인 것이 헷갈릴 수 있어 양쪽 주석에 서로를 적어 뒀다.

포커스 변화를 재생기가 할 일로 옮기는 `focusActionFor()` 를 순수 함수로 뺐다.
여기서 `AUDIOFOCUS_LOSS_TRANSIENT` 를 영구 손실로 다루면 **안내가 끝난 뒤 음악이
영영 돌아오지 않는다.** 상수 조합이 가장 틀리기 쉬운 자리라 테스트로 고정했다.

화면 규칙은 `docs/accessibility.md` 를 따랐다.

- **주 동작 하나.** 재생과 멈춤이 같은 자리의 같은 버튼이다. 둘로 나누면
  지금 어느 쪽인지 먼저 판단해야 한다. 글자와 아이콘이 같이 바뀐다 —
  색만 바뀌면 저대비 시력에서 구분되지 않는다.
- **진행 막대를 두지 않았다.** 작은 손잡이를 끄는 조작은 손 떨림이 있으면 거의 안 된다.
- **곡 목록을 나열하지 않았다.** 선택지가 많으면 결정을 못 한다. 앞/뒤로만 넘긴다.
- 권한은 시작할 때 묻지 않고 음악 화면에서 눌렀을 때만 묻는다. 처음 열 때
  대화상자가 연달아 뜨면 무엇을 허락하는지 모른 채 누르게 된다.

**에뮬레이터가 목록 캐시 버그를 잡아냈다.** 처음에는 `load()` 가 한 번 읽으면
다시 읽지 않게 해 뒀다. 재생 중에 목록이 바뀌면 같은 인덱스가 다른 곡을 가리키기
때문인데, 이 캐시가 **권한을 막 허락한 직후를 덮어버렸다** — 목록이 빈 채로
`loaded=true` 가 박혀서, 노래를 넣고 다시 열어도 "들을 노래가 없어요" 가 그대로 떴다.
조건을 "읽었는가" 에서 **"재생 중인가"** 로 바꿨다. 멈춰 있으면 매번 다시 읽는다.

**Pixel 6 · API 35 에서 확인한 것.** 실제 오디오 스택까지 봤다.

| | 결과 |
|---|---|
| 권한 거부 상태 · 허락 · 재조회 | 화면이 셋 다 맞게 갈린다 |
| 노래 0곡 | "들을 노래가 없어요" |
| 재생 | `MediaPlayer state:started`, 포커스 `gain: GAIN` / `USAGE_MEDIA` |
| 곡 끝 | 자동으로 다음 곡, 재생 유지 |
| **전화 착신** | `loss: LOSS_TRANSIENT` → `state:paused` |
| **통화 종료** | `loss: none` → `state:started` (스스로 복귀) |
| **안내 중 덕킹** | 아래 |

덕킹은 실제 여정으로 확인했다. 대전 좌표에서 대전시청까지 실데이터로 경로를 뽑고
(316번 · 7정거장 · 20분) 음악을 튼 채 안내를 시작했다.

```
VoiceGuide   gain: GAIN_TRANSIENT_MAY_DUCK    ← 도보 안내가 들어옴
MusicPlayer  loss: LOSS_TRANSIENT_CAN_DUCK    ← 음악은 작아지기만 한다
   … 안내 끝 …
MusicPlayer  loss: none                       ← 복귀
```

**음악이 한 번도 끊기지 않았다.** 3.6절이 의도한 그대로다.
긴급 안내(`CRITICAL`)의 일시정지 경로는 버스에 타야 나오므로 여정으로는 못 봤지만,
그것이 만드는 신호가 `LOSS_TRANSIENT` 로 전화 착신과 같아 위 표에서 이미 확인됐다.

> **아직 안 된 것 — 배경 재생.** 안내 중에는 `JourneyGuidanceService` 가 프로세스를
> 살려두므로 화면을 꺼도 노래가 이어진다. 그러나 **여정 없이** 음악만 틀고 앱을 나가면
> 시스템이 프로세스를 정리할 때 재생이 끊긴다. 제대로 하려면 `MediaSession` +
> `mediaPlayback` 포그라운드 서비스가 필요하다. #8(라디오)도 같은 것을 요구하므로
> 둘을 같이 붙이는 편이 낫다.

**#15 — TAGO 에 서울이 없다.** 같은 API 로 좌표만 바꿔 확인했다.

```
대전시청  → 28건    부산시청 → 19건    수원시청 → 15건
서울시청  →  0건    ←
```

서울은 자체 API 를 쓴다. 지금 이 앱은 서울에서 동작하지 않는다. 인구가 가장 많은 도시다.

**API 명세를 확보했다 (2026-08-09).** `api.bus.go.kr` 레퍼런스를 직접 받아
`docs/public-data-apis.md` §8 에 정리했다. 오퍼레이션은 지금 쓰는 TAGO 5종과
**1:1 로 대응한다** — 좌표 근접 정류소, 정류소 경유 노선, 노선 경유 정류소,
정류소·노선 도착예정, 노선 차량 위치가 전부 있다. 기능이 빠져서 막히는 것은 없다.

그런데 **그대로 갈아끼울 수는 없다.** 배선을 바꿔야 하는 것이 다섯 가지다.

| | 차이 | 영향 |
|---|---|---|
| 1 | **XML 전용.** `_type=json` 같은 스위치가 없다 | `NetworkModule` 이 Moshi 뿐이라 XML 컨버터가 필요하다. 가장 크다 |
| 2 | 정류소 식별자가 `stId`·`arsId` **두 개**고 오퍼레이션마다 요구하는 것이 다르다 | `BusStop.nodeId` 하나로는 안 된다 |

| 4 | 도착정보가 배열이 아니라 `...1`·`...2` 로 평탄화 | 저상버스가 `busType`(1:저상) 이라 `BusKind.from()` 이 안 먹는다 |
| 5 | `cityCode` 개념이 없다 | 지역 분기 키로 `cityCode` 를 쓰면 안 된다 |

**연동 배선은 하나도 없다.** `local.properties` 에 `SEOUL_OPEN_API_KEY=` 줄만 남아
있고 그 값을 앱으로 넘기는 `buildConfigField` 는 `build.gradle.kts` 에 없다 —
3.10절 미사용 항목 정리 때 빠졌다. 값을 채워도 도달할 경로가 없다.

> 그때는 이것 하나로 경로 탐색이 통째로 실패했고 오류는 키 문제처럼 보였다.

**#14 — 병·의원 API 의 한글 필터가 동작하지 않는다.**

같은 엔드포인트에서 값의 종류에 따라 갈린다.

```
QZ=B      (영문)  → 1432건   ✅
QD=D001   (영문)  → 23675건  ✅
필터 없음         → 78689건  ✅
Q0=서울특별시     →     0건  ❌
Q1=중구           →     0건  ❌
QN=<정확한 기관명>→     0건  ❌
```

인코딩을 네 가지로 바꿔 봤다 — UTF-8, UTF-8 이중, EUC-KR, 인코딩 없음.
**전부 0건이다.** 데이터에 실제로 있는 시도명(`dutyAddr` 의 "세종특별자치시")을
그대로 넣어도 0이므로 값이 틀린 것도 아니다. 서버 쪽 동작으로 본다.

그래서 `PlaceRepository.searchHospitals` 는 지금 구조로는 결과를 낼 수 없다.
선택지는 셋이다.

1. **주소검색(JUSO) 키를 받는다.** `local.properties` 의 `JUSO_CONFIRM_KEY` 가 비어 있다.
   원래 설계에서도 병원 검색과 주소 검색을 합치게 되어 있으므로 절반이 비어 있던 셈이다.
2. 병·의원은 `QZ`·`QD` 같은 영문 코드로만 받아오고 이름 대조는 앱에서 한다.
   전국 7만 8천 건이라 통째로 받을 수는 없다. 시도 필터가 안 되면 현실성이 없다.
3. 다른 장소검색 API 로 갈아탄다.

1번이 가장 현실적이다. [주소기반산업지원서비스](https://business.juso.go.kr) 에서 발급한다.

## 5. 확인 못 한 것 / 리스크

- **에뮬레이터 실행은 했지만 실기기에서는 돌려보지 않았다.** 홈·설정·검색 화면과
  인증키 오류 경로는 Pixel 6 API 35 에뮬레이터에서 확인했다. 다만 앱의 핵심
  (포그라운드 서비스 하차 알림, 실제 기기의 TTS 보이스 선택, 톡백 낭독)은
  전부 **실기기 런타임에만 드러나는 것들**이다.
  `VoiceGuide` 의 보이스 선택 규칙은 순수 함수만 테스트했고, `getVoices()` 를
  여러 화자가 설치된 환경에서 실제로 훑는 경로는 검증되지 않았다.
- **음질·문안 판단이 안 됐다.** 생성한 샘플을 직접 들어봐야 화자 선택과 이음매 자연스러움,
  바뀐 말투를 결정할 수 있다.
- **공공데이터 키는 있으나 필요한 데이터셋 활용승인이 없다.** 기상청에서 키 자체는
  인정됐고 TAGO·병의원 경로도 올바른 서버 오류 코드까지 확인했다. 성공 데이터의
  네트워크·파싱·경로탐색은 여전히 단위 테스트의 고정 응답으로만 확인된 상태다.
- ~~3.5절의 로그 마스킹은 고쳤지만 실제 로그로 확인하지 못했다.~~
  **확인됨(3.9절).** 실제 요청이 `serviceKey=***` 로 찍힌다.
- **아직 공공데이터 응답을 한 번도 성공적으로 받지 못했다.** 경로는 맞다는 것까지
  확인했으나(3.9절), 데이터셋 승인이 나기 전까지 경로 탐색·도착정보·하차 알림은
  통째로 미검증이다. 이 앱의 본체가 그대로 남아 있다.
- 클립 이어붙이기는 이음매에서 억양이 끊겨 들릴 수 있다. 심하면 슬롯 조합을 줄이고
  자주 나오는 조합을 통문장으로 미리 만드는 쪽으로 가야 한다.
  현재 샘플 기준 통문장 11.30초 vs 조각 이어붙임 10.03초 — 차이는 깎아낸 무음이다.
- 대기 안내에 "조금만 기다리시면 돼요" 가 붙어 문장이 길어졌다. 도착까지 남은 분이
  5·4·3·2 로 줄면 그때마다 전체 문장이 다시 나간다. 들어보고 거슬리면
  뒷문장은 처음 한 번만 붙이는 식으로 줄여야 한다.
