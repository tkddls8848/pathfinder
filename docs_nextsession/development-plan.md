# 개발 계획 — 음성 안내 개편 및 음악·라디오

작성 2026-08-05. 브랜치 `claude/elderly-wayfinding-app-mockup-sprelc`.

---

## 1. 배경

안내 음성이 기계음처럼 들린다는 지적에서 출발했다. 원인을 파 보니 두 층이었다.

| 층 | 원인 | 상태 |
|---|---|---|
| 음색 | 보이스를 고르지 않고 `setLanguage(KOREAN)` 만 호출 → 기기 기본(대개 최저품질 embedded) 보이스가 잡힘 | 1차 수정 완료, 빌드 미검증 |
| 문안 | 전부 합쇼체 명령형 (`~하세요`, `~습니다`) | 미착수 |

이후 **"무조건 사람 같은 음성이어야 한다"** 는 요구가 확정되면서 방향이 바뀌었다.
시스템 TTS는 기기마다 깔린 보이스가 달라 품질을 **보장할 수 없다**. 어르신 타깃일수록
저가·구형 단말 비중이 높아 최악의 경우를 밟을 확률이 오히려 크다.
설정에서 목소리를 고르게 하는 것도 답이 아니다 — 어르신이 조작해야 할 것이 늘고,
결국 보호자가 세팅해 줘야만 동작하는 기능이 하나 더 생긴다.

## 2. 확정된 방향: 음성을 미리 만들어 앱에 넣는다

이 앱은 자유 발화를 하지 않는다. 말하는 문장이 정해져 있다.

```
고정 문구      ~15개    "벨을 누르세요. 다음 정류장에서 내립니다."
숫자 슬롯     ~150개    숫자 0~9(버스번호) · 1~60분 · 1~30정거장 · 걸음 수
──────────────────────────────────────────────────────
              ~165개    opus 24kHz 모노 기준 1.5MB 이하 → 앱에 번들 가능
```

빌드 시점에 한 번 생성해 넣고 런타임에는 재생만 한다. 얻는 것:

- 기기와 무관하게 **항상 같은 사람 목소리**
- **완전 오프라인** — 버스 안에서 데이터가 끊겨도 하차 알림이 살아있다
- **설정 없음** — 어르신도 보호자도 건드릴 것이 없다

> 애초에 "음질이냐 오프라인이냐" 는 트레이드오프라고 판단했으나(로컬 보이스 우선 정책),
> 이 구조에서는 둘 다 성립한다. 그 트레이드오프 자체가 사라진다.

### 정류장·목적지 이름 — 유일한 예외

전국 정류장 이름을 미리 녹음할 수는 없다. 처리 방식:

1. 경로를 확정하는 시점(어르신이 집에서 "성모의원까지" 를 누를 때, 보통 와이파이)에
   그 여정에 필요한 이름 클립 2~6개만 받아 디스크에 캐시한다.
2. 버스 안에서는 캐시에서 오프라인 재생한다.
3. 못 받은 이름이 있으면 **그 문장 전체**를 시스템 TTS로 넘긴다.
   조각을 섞지 않는다 — 문장 중간에 목소리가 바뀌는 것이 가장 어색하다.

## 3. 지금까지 한 것

### 3.1 `VoiceGuide.kt` 보이스 선택 (커밋 전, 빌드 미검증)

- 한국어 보이스를 전부 훑어 최적을 골라 `setVoice()`.
  규칙: 한국어 && 설치됨 → 로컬 우선(없으면 네트워크) → 품질↓ → 지연↑ → 이름순
- 이름순 정렬은 품질·지연 동률일 때 **실행할 때마다 목소리가 바뀌지 않게** 하기 위한 것.
- 엔진은 시스템 기본을 존중. 기본 엔진이 한국어를 아예 못 할 때만 대체 엔진 최대 2개 시도.
- 견고화: `onInit` 을 메인 루퍼로 미룸(일부 기기에서 생성자 안 동기 호출),
  `getVoices()` NPE 방어, `setLanguage` 반환값 확인, 초기화 콜백 정확히 1회 보장,
  실패 시 죽은 엔진 바인딩 정리.
- `activeVoice: VoiceCandidate?` 노출 (진단용).
- 테스트 `app/src/test/.../VoiceSelectionTest.kt` 9케이스.
  `android.speech.tts.Voice` 는 단위 테스트에서 못 쓰므로 선택 규칙을
  `VoiceCandidate` 값 객체 위의 순수 함수로 분리.

> **2절 방향이 확정되면 이 코드의 위치가 바뀐다.** 폐기가 아니라
> "클립이 없을 때의 폴백 경로" 로 남는다. 폴백도 최선의 보이스를 써야 한다.

### 3.2 `docs/original-mockup.html` — 이후 저장소에서 제거됨

> 아래 작업은 실제로 했으나, 목업 파일 자체를 저장소에서 없애기로 하여 함께 사라졌다.
> 같은 종류의 버그가 앱에도 있었다는 기록으로 남긴다.

목업에 **앱과 똑같은 버그**가 있었다. `u.lang='ko-KR'` 만 주고 `u.voice` 미지정 →
Windows Chrome 이 Microsoft Heami(SAPI5)를 잡아 기계음이 났다.

- `speak()` → `say()` 로 통합하고 보이스 선택 추가.
  점수: 클라우드 +100, 이름에 `google` +50, `heami|sapi|microsoft` −50.
- devbar 에 목소리 드롭다운 + 들어보기 버튼 (개발 확인용, 실제 앱에는 없음).
- `busNear()` / `ringBell()` 이 각자 `SpeechSynthesisUtterance` 를 따로 만들던 것을 `say()` 로 합침.

목업은 **클라우드 보이스 우선**으로 앱과 반대다. 데스크톱 데모라 오프라인 제약이 없다.
이유는 코드 주석에 남겼다.

### 3.3 프로토타입 음성 샘플

무료 `edge-tts` (Microsoft Edge 읽어주기 엔진, API 키 불필요) 로 생성.
한국어 뉴럴 화자 3종: `ko-KR-SunHiNeural`(여) · `ko-KR-InJoonNeural`(남) ·
`ko-KR-HyunsuMultilingualNeural`(남). 속도 `-15%` (앱의 `speechRate 0.85` 대응).

실제 앱 문장 4개 × 3화자 + 이음매 확인용 조각 이어붙이기 1개 생성 완료.
SunHi 기준 통문장 7.82초 vs 조각 이어붙임 6.57초.

> ⚠️ **edge-tts 는 프로토타입 전용이다.** 생성 음성을 앱에 넣어 배포하는 것은
> Microsoft 약관 위반 소지가 크다. 파이프라인과 음질을 검증하는 용도로만 쓰고,
> 배포 전에 성우 녹음이나 라이선스가 명확한 유료 TTS로 반드시 교체해야 한다.

생성 스크립트는 현재 세션 스크래치패드에 있다. **저장소로 옮겨야 한다** (`tools/` 등).

### 문안 (미착수)

`JourneyController.kt` 의 안내 문장. 원칙은 **상황별 이원화**다.

```
긴급 3종 — 그대로 둔다 (몇 초 안에 움직여야 함)
├ "벨을 누르세요. 다음 정류장에서 내립니다."
├ "곧 내립니다. 일어날 준비하세요."
└ "○○입니다. 내리세요."

나머지 — 해요체로 (도보·대기·이동중·도착)
├ 약 150걸음 걸어서 성모의원으로 가세요.  → 이제 성모의원 쪽으로, 백오십 걸음쯤 걸어가시면 돼요.
├ 3분 뒤에 옵니다.                        → 삼 분 뒤에 와요. 조금만 기다리시면 돼요.
├ 계단 없는 저상버스입니다.               → 계단 없는 버스라 타기 편하실 거예요.
└ 도착했습니다. 성모의원 앞입니다.        → 다 왔어요. 성모의원 바로 앞이에요.
```

**수사 버그**: `JourneyController.kt:275` `"${remaining}정거장 남았습니다"` →
한국어 TTS는 `3정거장` 을 "삼 정거장" 으로 읽는다. 정거장은 순우리말 수관형사를
쓰는 단위라 **"세 정거장"** 이어야 한다. `busNumberToSpeech` 처럼 변환 헬퍼가 필요하다.
(`분` 은 한자어라 "삼 분" 이 맞으므로 그대로 둔다.)

### 음악·라디오 (신규)

이동 중 적적하지 않게 해달라는 요구.

**전제 조건 — 오디오 포커스 정책을 먼저 정한다.** 이 앱에서 절대 놓치면 안 되는 소리가
하차 알림인데 음악·라디오가 정확히 그것과 경쟁한다. 어르신이 라디오를 듣다 정류장을
지나치면 앱의 존재 이유가 무너진다. 재생 기능보다 먼저 정하고, 나중에 붙이지 않는다.

```
일반 안내 (도보·대기·이동중)  → 덕킹 (음악 볼륨만 낮춤)
긴급 안내 (벨·하차·하차준비)  → 완전 일시정지 후 안내 끝나면 복귀
```

| # | 작업 | 비고 |
|---|---|---|
| 6 | 오디오 포커스 정책 구현 | `AudioManager` focus request + 안내 우선순위 연동 |
| 7 | 음악 재생 | 기기 내 음원(MediaStore). 네트워크 불필요, 저작권 문제 없음 |
| 8 | 라디오 재생 | 스트림 소스 확보 방안과 저작권·안정성 검토 필요 |

UI 원칙: 어르신 조작 최소화. 큰 버튼, 선택지 적게. 기존 접근성 기준(`docs/accessibility.md`) 준수.

**라디오 미해결 이슈**: KBS·MBC·SBS 공식 스트림은 공개 API가 없고 토큰이 필요하다.
비공식 추출은 법적으로 불안정하고 잘 깨진다. 공개 디렉터리(Radio Browser API 등)로
갈지, 제휴를 받을지 결정이 필요하다.

## 5. 확인 못 한 것 / 리스크

- **빌드·테스트를 한 번도 돌리지 못했다.** 이 PC에 JDK 17도 Android SDK도 없고,
  `gradlew` 래퍼 스크립트가 저장소에 없다. `VoiceGuide.kt` 와 `VoiceSelectionTest.kt` 는
  눈으로만 검토한 상태다. 다음 세션 첫 작업으로 빌드 환경을 세우고 검증해야 한다.
- **음질 판단이 안 됐다.** 생성한 샘플을 직접 들어봐야 화자 선택과 이음매 자연스러움을
  결정할 수 있다.
- 목업의 보이스 선택 개선도 실제로 들어봐야 확인된다. 그 PC에 Google 한국어 보이스가
  없으면 개선 폭이 작다.
- 클립 이어붙이기는 이음매에서 억양이 끊겨 들릴 수 있다. 심하면 슬롯 조합을 줄이고
  자주 나오는 조합을 통문장으로 미리 만드는 쪽으로 가야 한다.
