# 음성 안내 설계

최종 갱신: 2026-08-08

화면을 읽기 어려운 어르신에게는 **음성이 주 출력**입니다. 그래서 TTS 를 "있으면 좋은
기능" 이 아니라 안내 파이프라인의 1급 출력으로 다룹니다. 이 문서는 무엇을 어떻게
말하는지, 그리고 왜 그렇게 정했는지를 적습니다.

접근성 수치(속도 0.85, 피치 1.0 등)의 근거는 [`accessibility.md`](accessibility.md) §4 에 있습니다.

---

## 1. 어떤 목소리로 말하는가

### 엔진이 주는 기본 보이스를 쓰지 않는다

`setLanguage(KOREAN)` 만 호출하면 엔진은 대개 **품질이 가장 낮은 embedded 보이스**를
줍니다. 안내가 로봇처럼 들리는 주된 이유가 이것이고, 같은 엔진 안에 더 좋은 보이스가
이미 깔려 있는 경우가 많습니다.

`VoiceGuide.selectBestVoice()` 가 한국어 보이스를 전부 훑어 고릅니다.

```
한국어 && 설치됨  →  로컬 우선(없으면 네트워크)  →  품질↓  →  지연↑  →  이름순
```

**네트워크 보이스는 품질이 더 높아도 뒤로 미룹니다.** 하차 안내가 꼭 나가야 하는 순간은
어르신이 버스 안에 있을 때이고, 그때 데이터가 끊기면 안내가 통째로 사라집니다.
로컬 보이스가 하나도 없을 때만 네트워크 보이스를 씁니다.

마지막 **이름순** 정렬은 품질·지연이 같은 보이스가 여러 개일 때 실행할 때마다 목소리가
바뀌지 않게 하려는 것입니다. 어르신에게는 목소리가 일정한 것 자체가 안내의 일부입니다.

엔진 자체는 시스템 기본을 존중합니다. 기본 엔진이 한국어를 아예 못 할 때만 설치된
다른 엔진을 최대 2개까지 시도합니다.

### 기기마다 다른 목소리가 잡힌다 — 그래서 화면에 보여준다

같은 앱이 기기마다 다른 목소리로 말합니다. "소리가 이상하다" 는 문의가 왔을 때
어떤 보이스가 물렸는지 모르면 재현할 방법이 없습니다.

설정 화면에 `VoiceGuide.activeVoice` 를 카드로 냅니다.

```
안내 목소리
ko-KR-x-ism-local
아주 좋음 · 기기에 저장됨
```

설정 화면의 사용자는 어르신이 아니라 보호자이므로 이 정도 기술적 표현이 허용됩니다.

### 견고화

기기별 TTS 구현이 제각각이라 방어가 필요합니다.

- `onInit` 을 메인 루퍼로 미룸 — 일부 기기는 생성자 안에서 동기 호출합니다
- `getVoices()` NPE 방어 — 여기서 죽으면 안내가 통째로 없어집니다
- `setLanguage` 반환값 확인 (`LANG_MISSING_DATA` / `LANG_NOT_SUPPORTED`)
- 초기화 콜백 정확히 1회 보장
- 실패 시 죽은 엔진 바인딩 정리

## 2. 무엇을 말하는가 — 문안

### 상황별로 말투를 이원화한다

```
긴급 (벨·하차준비·하차·승차신호)  →  명령형 그대로
나머지 (도보·대기·이동중·도착)    →  해요체
```

긴급 안내는 몇 초 안에 몸을 움직여야 하는 것입니다. 부드럽게 돌려 말하면
"지금 나한테 하라는 건가?" 를 판단하는 데 시간이 듭니다.

반대로 이동 내내 명령을 받으면 지시받는 기분이 듭니다. 옆에서 같이 가는 사람이
말하듯 하는 것이 목표입니다.

| 상황 | 문안 |
|---|---|
| 도보 | 이제 성모의원 쪽으로, 백오십 걸음쯤 걸어가시면 돼요. |
| 정류장 도착 | 중앙시장 정류장에 다 왔어요. 맞으면 네 여기예요를 눌러 주세요. |
| 대기 | 칠 공 일 육 번 버스가 삼 분 뒤에 와요. 조금만 기다리시면 돼요. |
| 저상버스 | 계단 없는 버스라 타기 편하실 거예요. |
| 승차 신호 | 칠 공 일 육 번 버스가 곧 와요. **손을 드세요.** |
| 이동 중 | 세 정거장 더 가면 내려요. |
| 하차 준비 | **곧 내립니다. 일어날 준비하세요.** |
| 벨 | **벨을 누르세요. 다음 정류장에서 내립니다.** |
| 하차 | **중앙시장입니다. 내리세요.** |
| 도착 | 다 왔어요. 성모의원 바로 앞이에요. |

굵은 것이 명령형을 남긴 것입니다. "손을 드세요" 는 3종에 없지만 성격이 같아
동작 부분만 명령형으로 두고 앞의 "곧 옵니다" 만 "곧 와요" 로 바꿨습니다.

### 눈으로 읽는 숫자와 귀로 듣는 수사를 분리한다

한국어 TTS 는 숫자를 보면 무조건 한자어로 읽습니다. 그래서 `3정거장` 이
"삼 정거장" 으로 나갑니다 — 한국어로는 틀린 말입니다.

```
정거장 · 걸음  →  순우리말 수관형사   "세 정거장", "스무 걸음"
분 · 번        →  한자어 그대로       "삼 분", "칠 공 일 육 번"
```

`VoiceGuide.nativeCountToSpeech()` 가 변환합니다. **백부터는 순우리말 수사가
현대어에서 쓰이지 않으므로**("백쉰 걸음") 숫자를 그대로 넘겨 TTS 가 한자어로 읽게 둡니다.
스물은 단독일 때 "스무", 뒤에 단위수가 붙으면 "스물세" 입니다.

버스 번호는 자릿수로 읽습니다. `7016` → "칠 공 일 육" 이어야 정류장 전광판과
대조해 들을 수 있습니다.

**말하는 곳은 `JourneyController` 만이 아닙니다.** 톡백이 읽는 `contentDescription`
도 같은 규칙을 따라야 합니다. 반대로 알림 텍스트는 잠금화면에서 눈으로 읽는 글자라
숫자를 그대로 씁니다.

| 위치 | 규칙 |
|---|---|
| `JourneyController` 안내 문장 | 수사 변환 |
| `GuidanceScreen` `spokenLabel` | 수사 변환 |
| `Components.BusNumberTag` `contentDescription` | 자릿수 읽기 |
| `JourneyGuidanceService` 알림 | **숫자 그대로** |

### 조사를 문자열에 붙이지 않는다

`"${정류장이름}으로"` 는 받침에 따라 `으로`/`로` 가 갈립니다. 정류장 이름은 전국에서
오므로 "센터으로" 가 나올 수 있습니다. `"~ 쪽으로"` 처럼 **조사가 고정되는 형태로
문장을 설계**해 문제를 없앱니다.

## 3. 다른 앱 소리를 어떻게 비키게 하는가

이 앱에서 절대 놓치면 안 되는 소리가 하차 안내입니다. 어르신이 라디오를 듣다
정류장을 지나치면 앱의 존재 이유가 없어집니다. 그렇다고 안내마다 음악을 멈추면
이동 내내 라디오가 끊깁니다.

`AudioAttributes` 만 설정하는 것으로는 아무 일도 일어나지 않습니다. 속성은
"내 소리는 이런 성격이다" 라는 선언일 뿐이고, 다른 앱을 실제로 비키게 하는 것은
**포커스 요청**입니다.

### Priority 3단계

| | 앞 문장 자름 | 다른 앱 소리 | 쓰는 곳 |
|---|---|---|---|
| `NORMAL` | 아니오 | 덕킹 | 도보·대기·이동중 |
| `INTERRUPT` | 예 | 덕킹 | 상태 전환 안내, 다시 안내받기 |
| `CRITICAL` | 예 | **일시정지** | 벨·하차준비·하차·승차신호 |

불리언 하나로는 두 축을 담을 수 없습니다. "앞 문장을 자를지" 와 "음악을 멈출지" 는
대체로 같이 가지만 늘 같지는 않습니다 — 정류장 확인 직후 노선 안내는 지금 알려야
하지만 라디오를 멈출 일은 아닙니다.

등급을 셋으로 끊은 이유는 **`CRITICAL` 을 아껴 쓰기 위해서입니다.** 음악을 멈추는
것은 어르신 입장에서 꽤 큰 개입이라 몇 초 안에 몸을 움직여야 하는 안내에만 씁니다.

### 포커스를 놓지 못하는 것이 진짜 위험이다

음악이 영원히 멈춘 채로 남고, 어르신은 왜 라디오가 안 나오는지 알 방법이 없습니다.
세 군데를 막아야 합니다.

- `QUEUE_FLUSH` 로 앞 문장을 자르면 **그 문장의 `onDone` 은 오지 않습니다.**
  자를 때 대기 목록을 같이 비웁니다.
- 엔진이 콜백을 끝내 주지 않는 경우가 있습니다. 30초 워치독이 강제로 놓습니다.
  가장 긴 안내가 12초 남짓이라 정상 동작을 자를 일은 없습니다.
- `stop()` · `shutdown()` 에서도 놓습니다.

`speak()` 는 안내 루프(백그라운드 코루틴)에서 불리고 포커스 해제는 메인에서 돕니다.
같은 필드를 만지므로 **포커스 조작은 전부 메인 큐로 몰아** 순서를 고정합니다.

### 못 받아도 말한다

다른 앱이 배타 포커스를 쥐고 있다는 이유로 하차 안내가 통째로 사라지는 것이
훨씬 나쁩니다. 반대로 통화 등으로 포커스를 **잃으면** 안내를 멈춥니다 —
얹어 봐야 둘 다 안 들립니다.

## 4. 확정된 방향 — 음성을 미리 만들어 앱에 넣는다

"무조건 사람 같은 음성이어야 한다" 는 요구가 확정되면서 방향이 정해졌습니다.

시스템 TTS 는 기기마다 깔린 보이스가 달라 품질을 **보장할 수 없습니다.**
어르신 타깃일수록 저가·구형 단말 비중이 높아 최악의 경우를 밟을 확률이 오히려 큽니다.
설정에서 목소리를 고르게 하는 것도 답이 아닙니다 — 어르신이 조작해야 할 것이 늘고,
결국 보호자가 세팅해 줘야만 동작하는 기능이 하나 더 생깁니다.

이 앱은 자유 발화를 하지 않습니다. 말하는 문장이 정해져 있습니다.

```
고정 문구      ~15개    "벨을 누르세요. 다음 정류장에서 내립니다."
숫자 슬롯     ~150개    숫자 0~9(버스번호) · 1~60분 · 1~30정거장 · 걸음 수
──────────────────────────────────────────────────────
              ~165개    opus 24kHz 모노 기준 1.5MB 이하 → 앱에 번들 가능
```

빌드 시점에 한 번 생성해 넣고 런타임에는 재생만 합니다. 얻는 것:

- 기기와 무관하게 **항상 같은 사람 목소리**
- **완전 오프라인** — 버스 안에서 데이터가 끊겨도 하차 알림이 살아있다
- **설정 없음** — 어르신도 보호자도 건드릴 것이 없다

> 애초에 "음질이냐 오프라인이냐" 는 트레이드오프라고 판단했으나(로컬 보이스 우선 정책),
> 이 구조에서는 둘 다 성립합니다. 그 트레이드오프 자체가 사라집니다.

이 방향이 확정되면 1절의 보이스 선택 코드는 **폐기가 아니라 "클립이 없을 때의 폴백
경로" 로 남습니다.** 폴백도 최선의 보이스를 써야 합니다.

### 정류장·목적지 이름 — 유일한 예외

전국 정류장 이름을 미리 녹음할 수는 없습니다.

1. 경로를 확정하는 시점(집에서 "성모의원까지" 를 누를 때, 보통 와이파이)에
   그 여정에 필요한 이름 클립 2~6개만 받아 디스크에 캐시한다.
2. 버스 안에서는 캐시에서 오프라인 재생한다.
3. 못 받은 이름이 있으면 **그 문장 전체**를 시스템 TTS 로 넘긴다.
   조각을 섞지 않는다 — 문장 중간에 목소리가 바뀌는 것이 가장 어색하다.

## 5. 문안을 귀로 확인하는 방법

기기에 올리지 않고도 들어볼 수 있는 자리가 둘 있습니다.

**`docs/original-mockup.html`** — 브라우저로 열면 화면 12개를 눌러가며 흐름 안에서
듣습니다. 패널에서 `고치기 전` / `고친 뒤` 를 눌러 같은 화면을 두 번 들으면 무엇을
왜 고쳤는지 확인됩니다. ⑨이동중의 "사 정거장" vs "네 정거장" 이 가장 분명합니다.

> **문안을 고치면 목업의 `SCRIPTS.after` 도 같이 고쳐야 합니다.**
> 앱과 다른 문장을 들으면 판단이 무의미해집니다.

목업은 앱과 반대로 **클라우드 보이스를 우선**합니다. 데스크톱 데모라 오프라인
제약이 없기 때문입니다. 이유는 파일 상단 주석에 있습니다.

**`tools/make_voice_samples.py`** — `edge-tts` 로 화자별 mp3 를 생성합니다.
결과는 `docs/voice-samples/` 에 떨어지고 `.gitignore` 에 있습니다.

> ⚠️ **edge-tts 는 프로토타입 전용입니다.** 생성 음성을 앱에 넣어 배포하는 것은
> Microsoft 약관 위반 소지가 큽니다. 파이프라인과 음질을 검증하는 용도로만 쓰고,
> 배포 전에 성우 녹음이나 라이선스가 명확한 유료 TTS 로 반드시 교체해야 합니다.
