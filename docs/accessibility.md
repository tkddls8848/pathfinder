# 노년층 접근성 설계 원칙

최종 갱신: 2026-08-08

이 앱의 UI 결정은 취향이 아니라 노화에 따른 신체·인지 변화에서 나옵니다.
"큰 글씨로 만들자"가 아니라, **무엇이 왜 어려운지**에서 출발합니다.

---

## 1. 시각

| 변화 | 결과 | 이 앱의 대응 |
|---|---|---|
| 노안 (수정체 조절력 저하) | 작은 글씨 초점이 안 맞음 | 본문 최소 **22sp**, 주요 버튼 **34sp**, 핵심 숫자 **88sp** |
| 대비 감도 저하 | 연한 회색 글씨가 안 보임 | 모든 조합 **7:1 이상** (WCAG AAA). "회색 보조 텍스트"도 9:1 |
| 백내장 (황변) | 파란 계열 구분이 어려움 | 색 단독으로 정보를 전달하지 않음. 항상 글자·크기와 함께 |
| 눈부심 / halation | 검은 배경 흰 글씨가 번짐 | 다크 모드를 기본으로 하지 않음. 켜도 순검정(#000) 대신 #1A1A1A |
| 주변시야 축소 | 화면 가장자리 요소를 놓침 | 중요한 것은 화면 중앙. 긴급 버튼만 하단 고정 |

**그림자를 쓰지 않습니다.** 대비 감도가 떨어지면 Material 의 elevation 그림자는
보이지 않습니다. 카드 경계는 전부 **4dp 실선 테두리**입니다.

---

## 2. 운동 기능

| 변화 | 결과 | 이 앱의 대응 |
|---|---|---|
| 손 떨림 (본태성 진전 등) | 작은 버튼을 빗나감 | 주 버튼 최소 높이 **96dp** (Material 권장 48dp의 2배) |
| 소근육 정밀도 저하 | 인접 버튼 오탭 | 버튼 간격 **16dp** 이상 |
| 관절염 | 스와이프·롱프레스·핀치가 어려움 | **탭 제스처만** 사용. 스와이프로만 되는 기능 없음 |
| 반응 속도 저하 | 타임아웃에 걸림 | 자동으로 사라지는 UI 없음. 음성 인식 침묵 허용 **3초** |

## 3. 인지

| 변화 | 결과 | 이 앱의 대응 |
|---|---|---|
| 작업기억 감소 | 여러 단계를 못 외움 | **한 화면 한 동작**. 주 버튼은 화면당 하나 |
| 선택 과부하 | 옵션이 많으면 결정 못 함 | 경로는 1개만 크게. 대안은 접어둠 |
| 새 개념 학습 부담 | 지도 축척·방위 개념이 어려움 | **지도를 기본으로 보여주지 않음**. 시간순 목록으로 대체 |
| 오류 후 복구 어려움 | 잘못 누르면 못 빠져나옴 | 모든 화면에서 되돌아갈 수 있음. 파괴적 동작엔 확인 단계 |

### 지도를 기본에서 뺀 이유

일반 길찾기 앱은 지도가 중심입니다. 그러나 지도를 읽으려면
① 축척 개념 ② 방위 개념 ③ 자기 위치와 지도상 점의 대응
세 가지를 동시에 처리해야 합니다. 인지 부하가 매우 큽니다.

대신 이 앱은 **"지금 무엇을 하면 되는지" 한 문장**만 보여줍니다.

```
    걸어가세요
      250
      걸음
  ┌──────────┐
  │ 중앙시장  │
  │ 정류장    │
  └──────────┘
```

## 4. 청각

- 난청은 **고주파부터** 옵니다 → TTS 피치를 올리지 않음 (1.0 유지)
- 발화 속도 **0.85배** — 기본값은 어르신에게 빠릅니다
- 버스 번호는 **자릿수로 읽음**: "7016" → "칠 공 일 육" (TTS 기본은 "칠천십육")
  정류장 전광판과 대조해서 들을 수 있어야 합니다
- 거리는 미터가 아니라 **걸음 수**로: "150m" → "약 이백삼십 걸음"
- 시끄러운 버스 안에서는 음성이 닿지 않음 → **진동 패턴이 독립적으로 의미를 가짐**
- 일반 안내는 다른 앱 소리를 낮추고, 하차·벨 같은 긴급 안내만 잠시 멈춥니다
- 실제 선택된 TTS 보이스와 품질·로컬 저장 여부를 설정 화면에서 확인할 수 있습니다
- 앱이 트는 음악에도 같은 규칙이 적용됩니다. 다만 **음악은 포커스를 못 받으면
  아예 재생하지 않습니다** — 안내와 정반대입니다. 안내는 못 받아도 말합니다

### 음악 화면

이동 중에 적적하지 않게 해달라는 요구에서 나왔습니다. 화면 규칙은 위와 같습니다.

| 결정 | 이유 |
|---|---|
| 재생·멈춤이 **같은 자리의 같은 버튼** | 둘로 나누면 지금 어느 쪽인지 먼저 판단해야 합니다 |
| 글자와 아이콘이 **같이** 바뀜 | 색만 바뀌면 저대비 시력에서 구분되지 않습니다 |
| 진행 막대 없음 | 작은 손잡이를 끄는 조작은 손 떨림이 있으면 거의 안 됩니다 |
| 곡 목록 없음 · 앞/뒤로만 | 선택지가 많으면 결정을 못 합니다 (§3 선택 과부하) |
| 목록 끝에서 처음으로 돎 | "다음 노래" 를 눌렀는데 아무 일도 없으면 고장으로 받아들입니다 |

권한은 앱을 처음 열 때 묻지 않고 **음악 화면에서 눌렀을 때만** 묻습니다.
대화상자가 연달아 뜨면 무엇을 허락하는지 모른 채 누르게 됩니다.

### 진동 어휘 (셋뿐)

많이 만들면 구분이 안 됩니다.

| 패턴 | 의미 |
|---|---|
| 짧게 1회 | 화면이 바뀜 (확인) |
| 짧게 2회 | 버스가 곧 옴 |
| 길게 3회 | **하차 준비 / 벨 누르기** — 가장 강한 신호 |

## 5. 이 앱에서 가장 중요한 설계 결정

### 5-1. 안내는 화면이 꺼져도 계속된다

목업에서는 버튼을 눌러야 다음 화면으로 갔습니다. 실제로는 그러면 안 됩니다.
어르신은 버스에 타면 휴대폰을 주머니에 넣습니다.

그래서 안내 진행은 UI 가 아니라 **포그라운드 서비스**에 붙어 있습니다
(`JourneyGuidanceService` + `JourneyController`).
화면을 꺼도, 다른 앱을 열어도, 하차 알림은 반드시 울립니다.

알림 자체도 안내 화면입니다. 잠금화면에서 글씨만 보고
"3정거장 남았습니다"를 알 수 있어야 합니다.

### 5-2. 승차 확인만 사람이 한다

상태 전이는 대부분 자동입니다. 딱 하나, **"네, 탔어요"** 만 수동입니다.
버스 승차를 자동 판정하다 틀리면, 타지도 않은 버스의 하차 알림이 울립니다.
오탐 비용이 너무 커서 여기만 사람에게 묻습니다.

### 5-3. 오류 메시지는 원인이 아니라 행동을 말한다

```
✗  HTTP 503 Service Unavailable
✗  공공데이터 API 응답 실패 (resultCode: 30)
✓  인터넷이 연결되지 않았습니다. 잠시 뒤 다시 해보세요.
✓  앱 설정에 문제가 있습니다. 가족에게 알려주세요.
```

어르신이 스스로 해결할 수 없는 문제(인증키 만료 등)는
**"가족에게 알려주세요"** 로 안내합니다. 이것이 정직한 안내입니다.

### 5-4. 설정 화면의 사용자는 어르신이 아니다

보호자가 씁니다. 그래서 설정 화면에서만 키보드 입력과 상대적으로 작은 글씨를 허용합니다.
다만 어르신이 실수로 들어와도 무언가를 망가뜨리지 않도록,
지우기 같은 동작에는 확인 단계를 둡니다.

## 6. TalkBack

시력이 많이 나쁜 어르신은 TalkBack 을 씁니다.

- 모든 버튼에 **문장형** `contentDescription`
  ("출발" ✗ → "출발합니다. 누르면 길안내를 시작합니다." ✓)
- 큰 숫자는 `mergeDescendants` 로 묶어 "3 정거장" 이 한 번에 읽히게
- 화면 제목에 `heading()` 시맨틱
- 이모지는 항상 글자와 함께. 단독으로 의미를 갖지 않음
- 한글은 음절 중간에서 줄바꿈되지 않도록 어절 내부에 워드 조이너를 넣되,
  TalkBack `contentDescription`에는 조이너가 없는 원문을 제공합니다

---

## 7. 검증되지 않은 것

정직하게 적어둡니다. 아래는 **실제 어르신 대상 사용성 테스트로 검증되지 않았습니다.**

- 96dp 터치 타겟이 실제 떨림 환자에게 충분한지
- 걸음 수 안내가 미터 안내보다 실제로 이해하기 쉬운지
- 진동 패턴 3종을 구분할 수 있는지 (특히 촉각 둔화가 있는 경우)
- 0.85배속 TTS 가 적절한지

수치들은 공개된 인간공학·접근성 가이드라인에 근거했지만,
**실사용 검증은 반드시 별도로 해야 합니다.**
