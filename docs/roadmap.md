# 남은 작업

최종 갱신: 2026-08-30

앱은 대전에서 끝까지 동작합니다 — 실시간 공공데이터로 환승 경로를 만들고, 위치가
움직이면 안내 단계가 스스로 넘어가고, 화면이 꺼져도 포그라운드 서비스가 하차를
알립니다. 이 문서는 **거기서 실서비스까지 남은 것**만 담습니다.

끝난 작업의 경위는 git 히스토리에 있습니다. 여기에 다시 적지 않습니다.

---

## 1. 출시를 막고 있는 것

심각도 순입니다.

### 서울에서 동작하지 않는다

TAGO 에 서울 버스 데이터가 없습니다. 좌표만 바꿔 확인했습니다.

```
대전시청 → 28건    부산시청 → 19건    수원시청 → 15건
서울시청 →  0건
```

서울시 자체 API 명세는 [`public-data-apis.md`](public-data-apis.md) §8 에 받아
정리해 두었지만 **배선은 하나도 없습니다.** `local.properties` 에
`SEOUL_OPEN_API_KEY=` 줄만 있고 그 값을 앱으로 넘기는 `buildConfigField` 가
`build.gradle.kts` 에 없어, 값을 채워도 도달할 경로가 없습니다.

붙이려면 다섯 가지가 바뀝니다 — XML 컨버터 추가(가장 큼), 정류소 식별자
두 개(`arsId`·`stId`) 병행 보관, `arrivalOf()` 시그니처에 순번(`ord`) 추가,
도착정보 파싱과 저상버스 판정 재작성, `cityCode` 를 지역 분기 키에서 제외.
data.go.kr 에서 서울 4종(15000303 · 15000193 · 15000314 · 15000332)을 각각
활용신청해야 합니다.

### 경로를 못 찾으면 55시간을 걸으라고 안내한다

`RoutePlanner.plan()` 은 정류소가 0건이거나 경로 후보가 비면 **거리와 무관하게**
도보 안내를 만듭니다 (`RoutePlanner.kt:101`, `:118`). 서울 좌표로 대전 목적지를
고르면 "걸어서 3336분"(약 55시간)이 그대로 나옵니다 — 2026-08-30 에뮬레이터 실측.

`WALK_ONLY_THRESHOLD_M = 700.0` 아래의 도보 안내(`:83`)는 의도된 것이지만
나머지 두 곳에는 상한이 없습니다. 주석은 "빈 화면보다 낫다"고 하는데, 어르신에게
55시간 도보를 안내하는 것은 빈 화면보다 나쁩니다. 서울에서는 정류소가 항상
0건이므로 **실사용에서 반드시 재현됩니다.**

폴백에 상한(예: 2km)을 두고 넘으면 "여기서는 버스로 갈 방법을 찾지 못했어요" 로
갈라 보냅니다. 서울 대응 전이라도 이것만으로 가장 위험한 오안내를 막습니다.

### 목적지를 이름으로 찾을 수 없다

검색 경로가 둘인데 둘 다 막혀 있습니다.

병·의원 API 는 서버가 한글 필터를 받지 않습니다. 인코딩 네 가지를 모두
시험했고 전부 0건이며, 응답에 실제로 들어 있는 시도명을 그대로 넣어도 0건입니다
([`public-data-apis.md`](public-data-apis.md) §2-7). 영문 코드 필터만 동작하므로
`PlaceRepository.searchHospitals` 는 지금 구조로 결과를 낼 수 없습니다.

대체 경로인 도로명주소 API 는 `JUSO_CONFIRM_KEY` 가 비어 있습니다. 코드는 이미
붙어 있어 **키만 받으면 검색이 살아납니다.** 원래 설계에서도 병원 검색과 주소
검색을 합치게 되어 있었으므로 절반이 비어 있던 셈입니다.
[주소기반산업지원서비스](https://business.juso.go.kr) 에서 발급합니다.
**가장 값싼 해결이자 최우선 항목입니다.**

### 배포용 음성 소스를 바꿔야 한다

현재 샘플은 edge-tts 로 만든 프로토타입이라 **약관상 배포 대상이 아닙니다**
(`docs/voice-samples/` 는 그래서 `.gitignore` 에 있습니다). 릴리스 전에
성우 녹음이나 유료 TTS 로 갈아끼워야 합니다. 아래 클립 파이프라인이
프로바이더 교체를 전제로 설계되어야 하는 이유입니다.

### 개발계정 한도로는 오래 못 간다

API 당 일 10,000 건입니다. 완화책 네 가지(노선 정류소 메모리 캐시, 적응형 폴링,
버스 도착 시 폴링 중단, 인증·할당량 오류 재시도 금지)가 들어가 있지만
실서비스는 운영계정 전환 + 활용사례 등록 후 한도 상향 신청이 필요합니다.
신청에 시간이 걸리므로 출시 일정보다 앞서 걸어 두어야 합니다.

## 2. 사용자 판단이 필요한 것 — 여기가 막혀 있다

**화자를 정해야 클립 파이프라인을 시작할 수 있습니다.** 3절이 통째로 이것에
묶여 있습니다.

| 판단 | 어떻게 확인하나 |
|---|---|
| 화자 선택과 이음매가 어색하지 않은지 | `docs/voice-samples/` 의 mp3 (edge-tts 3화자, 전후 대비 포함) |
| 바뀐 말투가 괜찮은지 | 같은 폴더의 전후 대비 샘플을 이어서 듣기. 문안 자체는 [`voice-guidance.md`](voice-guidance.md) §2 에 있습니다 |
| 화면 글자도 해요체로 바꿀지 | 지금은 음성만 해요체입니다. 화면은 "도착했습니다", 음성은 "다 왔어요" 로 톤이 어긋납니다. 화면은 짧아야 읽히므로 격식체가 유리한 면도 있어, 음성만 바꾼 채 두는 것도 선택지입니다 |
| 도보 걸음 수를 화면에서도 뭉갤지 | 음성은 십 단위로 뭉개는데 화면은 실측값(`153`)이 그대로 떠 위치가 갱신될 때마다 흔들립니다. 뭉개면 숫자가 안정되지만 접근성 결정이라 따로 판단이 필요합니다 |

---

## 3. 음성 클립 파이프라인

미리 만든 음성을 앱에 넣는 방향은 [`voice-guidance.md`](voice-guidance.md) §4 에
확정돼 있습니다. `VoiceGuide` 는 아직 시스템 TTS 기반이고 `app/src/main/assets/` 는
비어 있습니다 — **구현은 시작 전입니다.**

| 작업 | 비고 |
|---|---|
| 클립 매니페스트 + 생성 파이프라인 | 프로바이더 교체 가능하게. 성우·유료 TTS 로 갈아끼울 수 있어야 합니다 |
| 클립 재생 런타임 + 시스템 TTS 폴백 | `VoiceGuide` 를 재생 기반으로 전환. 폴백은 문장 단위 |
| 정류장·목적지 이름 사전 확보 | 이름은 미리 만들 수 없는 유일한 예외입니다. 경로 확정 시점에 프리페치 + 디스크 캐시 |

## 4. 음악·라디오

오디오 포커스 정책과 기기 내 음원 재생은 이미 서 있습니다 — 일반 안내는 덕킹,
긴급 안내(벨·하차·하차준비)는 완전 일시정지 후 복귀. 남은 둘은 같은 것을
요구하므로 **같이 붙이는 편이 낫습니다.** 라디오는 배경 재생이 없으면 의미가
없어 순서가 묶입니다.

| 작업 | 비고 |
|---|---|
| 배경 재생 | 여정 없이 음악만 틀고 앱을 나가면 끊깁니다. `MediaSession` + `mediaPlayback` 서비스 |
| 라디오 재생 | 자기 재생만 신경 쓰면 됩니다. 비켜주는 쪽은 `MusicPlayer` 의 포커스 처리를 그대로 따릅니다 |

**라디오 미해결 이슈**: KBS·MBC·SBS 공식 스트림은 공개 API 가 없고 토큰이
필요합니다. 비공식 추출은 법적으로 불안정하고 잘 깨집니다. 공개
디렉터리(Radio Browser API 등)로 갈지, 제휴를 받을지 결정이 필요합니다.

UI 는 어르신 조작 최소화 — 큰 버튼, 선택지 적게.
[`accessibility.md`](accessibility.md) 기준을 그대로 따릅니다.

## 5. 경로 품질

첫 실행에서 86 정거장·179 분짜리 경로가 나온 적이 있습니다. 난이도 점수는
`도보 × 1.6 + 버스 + 환승 × 8분` 으로 "가장 쉬운" 경로를 고르지만, 후보 자체가
빈약하면 이상한 것이 1등으로 올라옵니다. 여러 지역·시간대에서 실제 경로를
받아 보고 상한과 후보 생성 규칙을 조정해야 합니다.

## 6. 아직 확인 못 한 것

- **실기기에서 돌려보지 않았습니다.** 에뮬레이터에서 경로 탐색·안내 진행·포그라운드
  서비스까지 확인했지만, 실제 기기의 TTS 보이스 선택(`getVoices()` 를 여러 화자가
  설치된 환경에서 훑는 경로)과 TalkBack 낭독은 **실기기 런타임에만 드러납니다.**
- **맥에서 에뮬레이터 시험 절차를 돌려보지 않았습니다.** 리눅스(GitHub Actions
  러너)와 윈도우 11 은 `tools/desktop_run.py` 로 끝까지 확인했습니다. 맥은 OS 별
  분기를 코드로 갈라 두었을 뿐 전체를 돌려 본 적이 없습니다.
- **클립 이어붙이기의 이음매.** 억양이 끊겨 들릴 수 있습니다. 심하면 슬롯 조합을
  줄이고 자주 나오는 조합을 통문장으로 미리 만드는 쪽으로 가야 합니다.
  샘플 기준 통문장 11.30초 vs 조각 이어붙임 10.03초 — 차이는 깎아낸 무음입니다.
- **대기 안내 문장이 반복됩니다.** "조금만 기다리시면 돼요" 가 붙어 문장이 길어졌는데,
  도착까지 남은 분이 5·4·3·2 로 줄면 그때마다 전체 문장이 다시 나갑니다.
  들어보고 거슬리면 뒷문장은 처음 한 번만 붙이는 식으로 줄여야 합니다.
